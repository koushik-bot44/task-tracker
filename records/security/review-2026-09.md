# Orbit security review — September 2026

Phase 5 of the go-live programme, 2026-09-11. Base: commit f4963ec plus the Phase 5 changes committed with this file.

**Method.** Attacks ran only against the local clone (`orbit_clone`) and this machine's dev server, through `scripts/check-security.ts`, with throwaway accounts that the run removes (every table is recounted after). Production received read-only checks only: the response headers of `/login` and the status of a signed-out API call. The map of trust boundaries is `records/plans/architecture-map.md` (Trust boundaries, Traces 1 and 2).

## Critical — needs the owner now

### C1. The live CEO password is the demo password

- **Where.** Production account `founder@orbit.local`. The demo password is the default in several committed scripts (for example `scripts/check-after-reset.ts`, `scripts/rig-fixture-data.ts` and older rigs), in both remotes.
- **Risk.** `/login` is public. Anyone who can read the repository, or guess the demo password, can sign in to production as the CEO: every department, every person, Well Being.
- **Fix.** Change the CEO password today: Account → Password on the live site. It needs no deploy. Then change the CEO's sign-in email to a real one (Account → Sign-in email). The scripts' default only matters while production uses it.
- **Not tested on production.** Trying the password there would be an attack on the live site; this finding comes from the recorded state of the account.

## High

### H1. A reset link did not end older sessions — fixed

- **Where.** `app/api/invite/[token]/accept/route.ts`. An admin's password reset sends the same set-password link as an invite; accepting it set the password without changing `sessionVersion`.
- **Repro.** Sign in (session A). Issue a reset link for that account; set a new password through it. Session A still answered `GET /api/users/me` with 200.
- **Why it matters.** A reset is what someone does when their account was taken over; the intruder's session survived it. (Changing a password from Account already ended other sessions.)
- **Fix.** Accepting a link bumps `sessionVersion`; the new cookie carries the new version.
- **Guard.** `check-security`: "setting a password from a reset link ends the account's older sessions" — before: `accept 200; the older session answers 200`; after: pass.

### H2. Malformed order keys — fixed in Phase 4

- **Where.** `lib/validation.ts` accepted any non-empty `orderKey`; projects and tasks take their key after the last one.
- **Repro.** Anyone running a project sends `PATCH /api/projects/:id {"orderKey":"zzz"}`; the next `POST /api/projects` by anyone answers 500. The same for tasks outside a project.
- **Fix.** Every `orderKey` must be a key fractional-indexing itself would write (f4963ec).
- **Guard.** `check-edges`: "a malformed order key on a project / on a task is refused" — before: `200, then 500`; after: pass.

### H3. Personal email addresses in the repository

- **Found.** 8 distinct personal-mail addresses (Gmail, Yahoo, Hotmail and Outlook domains) in the committed tree, and more wherever history holds older copies.
- **Fixed here.** `scripts/check-mobile.ts` typed one as test input (now `kiran.home@example.com`); `scripts/remove-leftover-people.ts` kept a colleague's address in a list (removed).
- **Still committed** (paths only):
  - `records/snapshots/prod-dump-2026-09-03T17-48-30-301Z/user.json` — a production user dump
  - `records/snapshots/restructure-dump-2026-09-04T07-14-26-205Z/user.json` — a user dump
  - `records/snapshots/evidence-leadwipe-2026-07-22T20-56-44-663Z.json`
  - `records/snapshots/phase35-phase34-model-dump-2026-08-29T14-18-16-146Z.json`
  - `records/plans/restructure-plan.md`, `records/reports/restructure-report.md`, `records/verdicts.md`, `records/verdicts/restructure-owner-round-2.md`
- **Owner decision.** (a) Remove or redact these from the tree in a normal commit; (b) rewrite history to scrub them, which needs a force-push to both remotes and everyone re-cloning. (a) alone still leaves them in history.

## Medium

### M1. Security headers — fixed

- **Evidence (production, read-only, 2026-09-11).** `/login` answered with `strict-transport-security` (Vercel's own) and `x-powered-by: Next.js`, and none of: Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
- **Fix.** `next.config.mjs` sends, on every response: `Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'; object-src 'none'; form-action 'self'`, `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: microphone=(), geolocation=(), payment=(), usb=()`, and HSTS; `x-powered-by` is off. Framing stays allowed for Orbit itself because the PDF reader's fallback frames an uploaded file; the camera is not restricted because a phone photo comes through the file picker.
- **Not yet.** Scripts are not restricted (`script-src`): the layout's two inline scripts and Next's own would need nonces first.
- **Guard.** `check-security`, three header checks (login page, signed-out 401, signed-in page) — before: all three failed; after: pass. Re-check production after the deploy.

### M2. Sign-out does not revoke the token

- **Where.** `DELETE /api/auth` clears the cookie; the signed token (30 days) stays valid until `sessionVersion` changes.
- **Repro.** Copy the cookie, sign out, use the copy: `GET /api/users/me` answers 200.
- **Options for the owner.** (a) Signing out ends every session of the account (bump `sessionVersion`) — simple, but signing out on a phone also signs out the laptop; (b) a per-device revocation list — precise, more code; (c) a shorter token life with renewal while in use.

### M3. The sign-in throttle trusts `X-Forwarded-For`

- **Where.** `lib/login-attempts.ts` keys failures by the first `X-Forwarded-For` value.
- **Repro (clone).** Twelve wrong passwords, each with a different header value: throttled 0 times. From one address, the ninth try is throttled (pass).
- **Risk.** On Vercel the platform sets that header, so the bypass needs a path that avoids Vercel. **Recommendation.** Prefer the platform's own client-address header when present, and add a gentle per-account slow-down (not a lockout, which would let anyone lock the CEO out).

### M4. Meeting-reply links act on a plain visit

- **Where.** `app/r/[token]/page.tsx` writes the reply and tells the organiser when the page is opened.
- **Risk.** Mail security scanners open links; a "Can't" could be recorded, and the organiser told, without the person choosing it.
- **Option for the owner.** The page shows the choice and a Confirm button that posts it.

## Low

- **L1. Uploads are checked by name and declared type, not contents.** A program renamed to `.pdf` is accepted and served as `application/pdf` with `nosniff`; web pages, SVGs and every other non-inline type download sandboxed (guarded in `check-security`).
- **L2. Cron secret compared with `!==`.** Timing leaks are impractical over the network here; a constant-time compare would be tidier.
- **L3. Notes on a task in no project through `/api/comments`.** `canAccessTask` refuses a task in no project, so that thread answers 404 even to its people (task notes themselves go through `/api/tasks/:id/comments`, which works). A functional gap, not a leak.
- **L4. Delete rights inside a department are broad.** A lead or above who can see a department's project may delete its tasks. Confirm this is intended.
- **L5. A database stall over about 5 s answers a generic 500** (nothing is half-written; `check-failure`).
- **L6. The API accepts an empty task title** (the screen asks for one).

## What held (check-security, after the fixes)

- Tokens: a changed signature, another key, an unsigned token claiming the CEO, and an expired token are all refused.
- Sessions: a password change, switching an account off and demoting a manager take effect on open sessions at once.
- Sign-in: the ninth wrong password from one address is throttled, and so is the right one straight after; a real and an unknown address fail alike, at sign-in and at forgot-password; first-run set-up stays shut once an account exists.
- Across departments: someone in another department cannot read (by id or number), change, delete, write on, take, or open the files of a task; a manager there cannot hang a meeting on it.
- Positions: nobody raises their own position or invites above it; a manager cannot place people in another department.
- Privacy walls: a private note is hidden even from the CEO and the owner's manager; a Well Being login and the admin reach no work; Well Being is the CEO's alone.
- Input: script in a title or description never runs on the record, the list or Today; an uploaded web page and an SVG with a script download sandboxed; text with a script is served as `text/plain` with `nosniff`; upload addresses cannot climb out of the store; a 5 MB title is refused; a quote in a search is only text.
- A form on another site cannot create a task with the person's cookie (SameSite=Lax); cron jobs refuse a caller without the secret.
