# Orbit Child — iOS

The iOS side of the Orbit Child phone app: a Capacitor 8 shell (the screens in
`mobile/www`) plus a native Swift plugin, `ChildTracker`, that pairs the phone,
keeps the device token in the Keychain, collects location in the background with
Apple's own background-location modes, queues every fix on disk, uploads it,
sends heartbeats and answers Locate Now.

The contract is `records/plans/device-tracking-plan.md` (sections 5, 7, 9, 10, 11).

> **Status (2026-09-29): not built yet.** These sources were written on a Mac
> with only the Command Line Tools: no Xcode, no iOS SDK. Every Swift file passes
> `swiftc -parse` (syntax only). **Nothing has been type-checked, compiled or run.**
> The first build in Xcode may show compile errors that only the iOS SDK can
> reveal. Fix those first, then run the test list at the end on a real iPhone.

2. Drag `App.entitlements` and `PrivacyInfo.xcprivacy` into the **App** group

4. Put back the edits to `AppDelegate.swift`, `SceneDelegate.swift`,
   `Main.storyboard` and `Info.plist` (they are in git).

## 2. First build (a Mac with Xcode 16 or newer)

```sh
cd mobile
npm install
# set serverUrl in www/config.js (e.g. "https://orbit.example.com") for the build you hand out
npx cap sync ios        # copies www/ into the app, writes CapApp-SPM/Package.swift
npx cap open ios        # opens ios/App/App.xcodeproj
```

Xcode resolves the Swift package `capacitor-swift-pm` 8.5.2 the first time
(needs internet). There is no Podfile and no workspace.

### Signing, team, bundle ID

Target **App** → *Signing & Capabilities*:

- **Team**: the Apple Developer team. *Automatically manage signing* on.
- **Bundle Identifier**: `com.sgroup.orbit.child` (already set; it must match
  `APNS_BUNDLE_ID` on the server).
- Deployment target: iOS 15.0 (template default; the code uses iOS 14+ APIs).

### Capabilities

They are already declared in `Info.plist` and `App.entitlements`; check that
Xcode shows them, and add them with **+ Capability** if not:

- **Background Modes**: ☑ Location updates, ☑ Remote notifications, ☑ Background fetch.
  Nothing else.
- **Push Notifications**. With automatic signing Xcode enables Push for the
  App ID in the developer portal.

`aps-environment` says `development`. Builds run from Xcode use the APNs
**sandbox**; an archive signed for TestFlight or the App Store gets `production`
from its provisioning profile. The token differs between the two, so the
server's `APNS_ENVIRONMENT` must match the build the child has installed (next section).

## 3. APNs key and the server's environment (Locate Now push)

APNs is optional. Without it Locate Now still works, just later: the request is
picked up at the phone's next heartbeat or wake.

1. developer.apple.com → *Certificates, Identifiers & Profiles* → **Keys** → **+**,
   tick **Apple Push Notifications service (APNs)**, save, **download the `.p8` once**
   (Apple never shows it again). Note the **Key ID**.
2. The **Team ID** is at the top right of the developer portal (Membership).
3. On Vercel (Project → Settings → Environment Variables), then redeploy:

| Variable | Value |
|---|---|
| `APNS_KEY_ID` | the key's 10-character ID |
| `APNS_TEAM_ID` | the team's 10-character ID |
| `APNS_PRIVATE_KEY` | the whole `.p8` file, `-----BEGIN PRIVATE KEY-----` … `-----END PRIVATE KEY-----`; on one line with `\n` for the line breaks is fine (`lib/device-push.ts` unescapes it) |
| `APNS_BUNDLE_ID` | `com.sgroup.orbit.child` |
| `APNS_ENVIRONMENT` | `sandbox` for a build run from Xcode; `production` (or anything other than `sandbox`) for TestFlight / App Store |

The server already sends what iOS needs for a silent push: payload
`{ "aps": { "content-available": 1 }, "type": "LOCATE_NOW", "requestId": "…" }`
with headers `apns-push-type: background`, `apns-priority: 5`, `apns-topic: <bundle id>`.
No alert, no sound: nothing is shown on the child's screen.

## 5. How it behaves

- **Pairing**: `pair({serverUrl, code})` → `POST {serverUrl}/api/device/pair`
  `{code, platform:"IOS", appVersion, model, osVersion, name}`. The token goes to
  the Keychain (`kSecClassGenericPassword`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`);
  device id, child's name and server address go to UserDefaults. The token is never
  returned to JavaScript. Release builds refuse any address that is not `https://`;
  DEBUG builds also accept `http://` for a development server. An address typed
  without a scheme gets `https://` in front.
  Errors in plain words: 404 / `PAIRING_INVALID` → "That code didn't work. Ask your
  parent for a new one."; 429 → "Too many tries. Wait a minute and try again.";
  no connection → "Can't reach <address>. Check the address and the internet."
- **Tracking** starts only when paired **and** the permission is *Always*.
  Standard updates (distance filter from the server config, default 50 m; 100 m
  accuracy while still, 10 m while moving faster than 1.5 m/s, back to still after
  10 min), `pausesLocationUpdatesAutomatically = true`, `activityType = .other`,
  `allowsBackgroundLocationUpdates = true`, **`showsBackgroundLocationIndicator = true`**
  (the blue indicator is always visible). Also significant-location changes and
  visits, so iOS relaunches the app after it is terminated or the phone restarts.
  When iOS pauses updates (standing still), a 150 m exit region, a significant
  change or a visit starts them again.
- **Every fix goes to disk first** (`Application Support/OrbitChild/location-queue.jsonl`,
  excluded from backups), with a UUID `clientId`, the fix's own time
  (`location.timestamp`), accuracy, altitude, speed, course, trigger, battery,
  charging and network. A standard fix is queued at most once per
  `movingIntervalSeconds` (default 120 s, like Android); Locate Now, Send now,
  visits and the first fix after a restart are always queued.
- **Upload**: `POST /api/device/locations` in batches of `maxBatch` (200), Locate Now
  fixes first, inside a `beginBackgroundTask`. Rows are deleted only after a 200
  answer (accepted, duplicate and rejected all count as answered). No connection or
  5xx → kept, retried with backoff (30 s doubling to 15 min) and at the next wake;
  429 → wait for `Retry-After` (default 60 s); 400/413 → smaller batches, never a
  deletion. `401 DEVICE_REVOKED` / `DEVICE_UNAUTHORIZED` → token and queue erased,
  location stopped, the app shows "This phone was removed".
- **Heartbeat** (`POST /api/device/heartbeat`): at every launch (event `BOOT` after a
  restart, `APP_OPEN` when the child opened the app, else `PERIODIC`), on any change of
  permission / precise location / Location Services / notifications
  (`PERMISSION_CHANGED`), at upload time when more than `heartbeatSeconds` (900 s)
  have passed (`PERIODIC`), from `BGAppRefreshTask` `com.sgroup.orbit.child.heartbeat`
  when iOS runs it, after Send now (`APP_OPEN`) and after a failed Locate Now
  (`LOCATE_NOW`). It carries `pushProvider: "APNS"` and the hex token once APNs registered.
- **Locate Now**: a silent push or a `locateRequests` entry in any answer →
  `DELIVERED` → one fresh fix (`requestLocation()`, or the running updates at 10 m and
  no distance filter) → queued with trigger `LOCATE_NOW` and the request id → uploaded
  → `completionHandler(.newData)`. No permission → `FAILED PERMISSION_DENIED`;
  Location Services off → `LOCATION_DISABLED`; no fix in time → `TIMEOUT`. The fix
  wait is `locateTimeoutSeconds` (30 s) with the app open, and at most 20 s in the
  background so the upload fits in iOS's ~30 s. iOS's push handler is always answered
  within 27 s.
- **Status for the screen** (`getState` / `stateChange`): `permission`,
  `preciseLocation` (null until location is allowed), `locationEnabled`,
  `notificationsAllowed`, `batteryOptimized: null` (no such thing on iOS),
  `trackingState` (`RUNNING` when tracking is on and can collect; `STARTING` only in
  the moments after a restart before the phone is first unlocked; else `STOPPED`),
  `lastFixAt`, `lastUploadAt`, `lastUploadError`, `queueSize`.

## 6. What iOS does NOT guarantee (tell the family)

- **Force-quit.** If the child swipes Orbit Child away in the app switcher, iOS
  stops standard location updates and does not deliver silent pushes or background
  refresh to it. Significant-change / visit / region events *may* still relaunch it in
  some cases, but Apple does not promise it. The parent then sees the phone go stale
  ("Phone unreachable") until the app is opened again. Nothing in the app tries to
  prevent or hide a force-quit.
- **Silent pushes** are best effort: iOS may delay, batch or drop them (Low Power
  Mode, poor battery, too many pushes, Background App Refresh off, force-quit).
  The parent sees an honest "waiting" state, and the request is also answered at the
  phone's next heartbeat or wake.
- **BGAppRefreshTask** runs when iOS decides, if ever (it learns from how often
  the app is used; never in Low Power Mode or with Background App Refresh off).
  It is a bonus, not a schedule.
- **Timing.** iOS decides when locations arrive. While still, updates pause; a
  significant change is roughly 500 m; visits arrive late. "Every N minutes" is not
  something iOS offers.
- **After a restart** nothing can be read or written until the phone is unlocked
  once (Keychain and files are protected until first unlock). Fixes that arrive
  before that are held in memory; if iOS ends the app first, they are lost.
- **"While Using" only**: no background collection; Locate Now fails with
  `PERMISSION_DENIED` unless the app is open.
- **Reduced accuracy** (Precise Location off): fixes are real but can be kilometres
  off; they are sent with their accuracy, and the parent sees it.
- **Airplane mode / no network**: fixes queue on disk and upload later; the parent
  sees them marked "arrived later".

## 7. Manual test checklist (a real iPhone; the simulator cannot do this)

Run with the server's `/api/routine/location/latest` and the parent's Location tab open.

1. **Pair**: install, enter the address and the parent's code. Wrong code → "That code
   didn't work…". 9 wrong codes in a minute → "Too many tries…". Right code →
   "Hi <name>", the parent's Phones list shows the iPhone (model, iOS version).
2. **When In Use, then Always**: tap *Allow location* → iOS asks → *Allow While Using
   App* → the parent sees `WHILE_IN_USE`. Tap *Always allow* → *Change to Always Allow*
   → banner "Sharing is on", `trackingState RUNNING`, the blue indicator appears in the
   status bar when the app is in the background. Tap *Always allow* again after
   answering *Keep Only While Using*: Settings opens (iOS asks only once).
3. **Precise off / Location Services off**: switch each off in Settings → the parent sees
   the issue within a heartbeat (`PERMISSION_CHANGED`) the next time the app wakes; switch
   back → tracking resumes.
4. **Lock 30 min**: lock the phone, walk or drive for 30 min → points arrive during
   the walk, blue indicator visible, spacing about 2 min while moving.
5. **Force-quit, then walk 1 km**: swipe the app away, walk more than 1 km. Record
   honestly whether iOS relaunched it (points resume) or not (parent sees
   "Unreachable" until the app is opened). Either is expected iOS behaviour.
6. **Reboot**: restart the phone, unlock it, move 1 km → the heartbeat says `BOOT`, the
   first point has trigger `BOOT`, history shows the gap.
7. **Airplane mode**: 20 min with airplane mode on while moving → `queueSize` grows on the
   status screen; switch it off → the queue drains, points appear with their real times,
   marked "arrived later".
8. **Low Power Mode**: on for an hour → note what arrives. Silent pushes are likely
   delayed; standard updates continue while the app is not force-quit.
9. **Revoke from the parent screen**: *Remove* the phone → at the next upload or
   heartbeat the app shows "This phone was removed…", the blue indicator goes away,
   `queueSize` 0. Pair again with a new code works.
10. **Locate Now with APNs** (server `APNS_*` set, matching sandbox/production): app in
    background, press Locate Now → "Sent to the phone" → "Updated a few seconds ago"
    within about 30 s. With the phone locked. With permission set to *While Using* →
    "FAILED PERMISSION_DENIED". With Location Services off → `LOCATION_DISABLED`. Indoors
    with no fix → `TIMEOUT` after about 20 s.
11. **Locate Now without APNs** (unset `APNS_*`) → the request stays "waiting" and is
    answered at the phone's next heartbeat or wake (open the app to see it answered at once).
12. **Send my location now** on the status screen → "Last sent: just now"; with location
    off → a plain-words error.
13. **Reinstall**: delete the app and install again → it asks for a new code (the old
    token left in the Keychain is dropped on first launch).

## 8. Choices made where the contract left room

- **Local plugin registration**: `OrbitBridgeViewController.capacitorDidLoad()` calls
  `bridge?.registerPluginInstance(ChildTrackerPlugin())`. The Capacitor 8 SPM template's
  `SceneDelegate` creates the root view controller in code, so it was changed too; the
  storyboard points at the same class. In the web view the plugin is
  `Capacitor.Plugins.ChildTracker` (`app.js` falls back to it because no
  `@capacitor/core` bundle is loaded).
- **Uploads use a normal URLSession inside `beginBackgroundTask`**, not a background
  `URLSession` configuration (the plan mentions one). Batches are small; if iOS suspends
  mid-upload, the rows are still on disk and the retry sends the same `clientId`s, which
  the server counts as duplicates.
- **Standard-fix spacing** uses the server's `movingIntervalSeconds`.
  `stationaryIntervalSeconds` is not used on iOS: iOS does not deliver time-based updates
  while still (the distance filter and the pause do that job).
- **Visits** are queued as points: iOS's own coordinate and arrival/departure time for a
  place, with its accuracy and without battery/network (those are only known for "now").
- **Boot detection** reads `kern.boottime` with `sysctlbyname` to send `event: BOOT` and
  `bootedAt`. It is not one of Apple's listed "required reason" APIs as of writing; if App
  Review objects, delete the `DeviceInfo.bootTime()` uses and launches report
  `APP_OPEN`/`PERIODIC` instead.
- **`requestForegroundPermission` opens Settings when location is already denied**
  (iOS will not ask again), like `requestBackgroundPermission`.
- **`requestBackgroundPermission`** opens Settings when iOS shows no question within
  1.5 s (iOS asks *Change to Always Allow?* once per app lifetime).
- **Notifications**: silent pushes do not need the child's notification permission on
  iOS. The app still asks (the checklist step) and reports the answer; no visible
  notification is ever posted.
- **Locate Now in the background waits at most 20 s for a fix** (the configured 30 s
  applies with the app open), so the upload fits in iOS's ~30 s budget.
- **Re-pairing** clears the queue first: fixes taken under an earlier pairing are not
  sent under a new one.
- **`UIDevice.current.name`** is sent as `name`; since iOS 16 it is usually just "iPhone"
  unless Apple grants the user-assigned-device-name entitlement.
- **The model** is the hardware identifier (`iPhone15,2`), not a marketing name.
